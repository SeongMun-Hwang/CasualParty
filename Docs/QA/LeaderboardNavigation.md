# 리더보드 진입과 상단 UI

## 구현
- Title: 게임 목록 Content의 RankingsBtn을 Canvas 바로 아래 우상단으로 이동. Google Play Games 기본 전체 리더보드 목록을 연다.
- Blockdoku / 10SUM: TopUIPanel의 트로피 버튼이 해당 게임 리더보드를 연다.
- MineSweeper: 플레이 중에는 선택한 난이도의 리더보드를 연다. 난이도 선택 전에는 지뢰찾기 난이도별 순위 선택창을 연다.
- 미로그인 상태에서는 로그인 안내창을 표시한다. 로그인 성공 시 처음 요청한 리더보드를 이어서 연다. 게스트 플레이를 유지할 수 있다.
- 상단 첫 줄: 왼쪽 타이머(있는 게임), 중앙 현재 점수, 오른쪽 순위 / 설정 팝업 버튼. 둘째 줄: 오른쪽 정렬한 최고 점수. 지뢰찾기는 중앙에 남은 지뢰 수, 둘째 줄 오른쪽에 선택한 난이도의 최고 시간을 표시한다.
- 설정 팝업: 배경음 / 효과음 / 진동의 기존 슬라이더·음소거 버튼을 세 줄로 정렬하고, 아래에 타이틀 이동 / 재시작을 배치했다. 닫기 버튼, 바깥 영역, Android 뒤로가기로 닫는다. Blockdoku의 재시작 확인창과 기존 광고 처리 경로를 유지한다.
- 설정 팝업을 여는 동안에도 게임 입력과 타이머 진행을 중지한다.
- 순위 로그인 안내, 점수 전송 대기, Google 기본 순위 UI가 열려 있는 동안 게임 입력과 제한시간 진행을 중지한다.

## Android 실기기 확인
1. 로그인 계정으로 메인 우상단 트로피 → Google 전체 리더보드 목록과 닫기 동작 확인.
2. 각 게임 트로피 → 해당 게임만 표시되는지 확인. 지뢰찾기는 세 난이도 각각 확인.
3. 게스트에서 게임 순위 → 로그인 → 처음 요청한 순위로 연결되는지 확인. 취소하면 게임 계속 가능해야 한다.
4. 10SUM / 지뢰찾기에서 순위창을 10초 이상 열었다 닫아 타이머가 유지되는지 확인.
5. 점수 업로드 중 연타, 순위 UI에서 Android 뒤로가기, 네트워크 끊김 후 재시도 확인.
6. 16:9 / 긴 화면 / 디스플레이 컷아웃 기기에서 상단 버튼, 통계, 플레이 영역의 가림 여부 확인.

배치는 씬에 저장된다. 재적용 도구는 Tools > Casual Party > Apply leaderboard layout이며 네 씬을 수정하므로, 수동으로 배치를 다듬은 이후에는 다시 실행하지 않는다.

## 검증 기록 (2026-11-06)
- 분리한 Unity 6000.3.10f1 프로젝트: 회귀 테스트 17개 통과. 네 씬의 순위 범위·버튼 위치·영구 클릭 연결, 지뢰찾기 새로 시작 연결, 순위창 표시 중 10SUM 타이머 정지 및 닫은 뒤 재개를 포함한다.
- Android 조건부 코드를 포함한 C# 컴파일 통과. APK 빌드 및 Google 기본 UI의 실기기 동작은 위 절차로 별도 확인한다.
- 1080×1920 씬 렌더링으로 상단 배치 확인. 에디터 렌더링에서는 런타임에 생성되는 게임판이 생략될 수 있다.
- 결과 파일: `LeaderboardNavigationRegressionResults.xml`.

## 공통 설정 팝업 검증
- 상단의 현재 점수 중앙 배치, 최고 기록의 둘째 줄 오른쪽 정렬, 순위 → 설정 버튼 순서를 씬에서 확인한다.
- 세 게임 모두 팝업 내부로 타이틀 이동 / 재시작이 이동했는지 확인한다.
- 10SUM 실플레이 테스트에서 배경음 슬라이더 값 저장, 음소거 / 해제 시 값 복구, 팝업을 연 동안 타이머 정지를 확인했다. 기존 검증과 함께 17개 테스트 통과.
- Android 조건부 C# 컴파일 통과. 실제 음량·진동 반영과 컷아웃 기기 터치 영역은 실기기에서 확인한다.
- `UnifiedHeaderRegressionResults.xml`에 최신 자동 테스트 결과를 저장한다. `Previews/UnifiedHeader.png`, `Previews/GameMenuPopup.png`는 에디터 렌더링이며 플레이 중 생성되는 게임판은 생략되어 있다.
